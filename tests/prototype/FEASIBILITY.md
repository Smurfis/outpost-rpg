# Fractal Island cave sections

Run `tests/prototype/chamber.tscn` to inspect the two chambers. Space opens the section, the arrow keys orbit by 90 degrees, Tab changes rooms and a left click prints the hit on the visible shell. From the project directory, Godot's `--rendering-method gl_compatibility --script res://tests/prototype/capture.gd` reproduces the four PNGs in `artifacts/cave_render/voxel-section/`.

The original 19 × 10 × 7 voxel volume supplies the movement collider and a shadow-only mesh. For each distinct room and camera sector the prototype builds a second mesh by testing each retained voxel's six neighbours. An excluded neighbour exposes a textured quad, including the floor rim and wall end caps. The same triangles supply the pick collider on a separate query layer. The normal adventurer, equipment and interior lights are scene objects independent of the section.

The desktop GL Compatibility run generated 45 newly exposed faces in each view of the first room and 44 in the second. The capture checks sampled the roof at Y=5 and the exposed floor at Y=0 from the same screen coordinate, confirmed the first roof closed, and revisited a cached view without remeshing. Visible limitations include strong point-light shadows and the still-roofed neighbouring room occupying some foreground after rotation. The fixture uses a known doorway, rectangular shells and fixed floor/ceiling heights. These assumptions should stay in the fixture.

## Integration path

- **Island streamer and topology.** In `island_archipelago.gd`, start with the current walkable floor from `terrain.caves.floors`. Segment connected headroom across traversable steps and stop at passage necks. Track the last chamber across a doorway. Use the actual 3D occupancy from `terrain.is_solid` and the local ceiling profile to classify overhead rock and camera-side occluders. Rectangular room bounds would remove unrelated rock on bends. Test concave rooms, multiple elevations and rays grazing an adjacent room before enabling this on real islands.
- **Mesh and streaming.** Keep `greedy_mesher.gd`'s atlas material and tiled quad UVs. Apply the occupancy predicate before face extraction or merging. Replace only the visible surfaces of chunks intersecting the section and its cut boundary. Query a one-voxel apron across chunk boundaries and give each face to its retained voxel's chunk. Publish matching visual and pick meshes together, restore original meshes on exit and evict section variants when their chunks unload.
- **Lighting, ocean and picking.** Keep the original movement collider and shadow-only mesh. Apply the current mobile shadow budget to the shadows. The production picker should query visible ground proxies alongside entities, skipping the original ground collider only for replaced chunks. `voxel_biome.gd` remains responsible for the water horizon and land mask. Repeat the real island capture to verify no water crosses the section, especially at shore-level floors. This fixture has no ocean.
- **Android.** The fixture uses ordinary indexed-by-state mesh resources, SurfaceTool, triangle collision and the existing atlas shader in desktop GL Compatibility. Android has not been measured. Profile cold remesh time, physics shape construction, cached mesh memory and orbit frame times on a device. Bound the cache and spread cold chunk builds over the existing streaming budget before shipping. A voxel ray query could avoid cooking extra pick shapes if device profiling identifies that cost as significant.
